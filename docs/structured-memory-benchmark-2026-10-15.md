# 구조화 기억 읽기 실측 (2026-10-15)

8개 합성 사례에서 실제 모델 답변을 비교했다. 기존 `read_evidence + trace_evidence`의 정답률은
75%, 구조화 `read_evidence`는 87.5%였다. 차이는 기존 300자 발췌 뒤에 있던 정정문을 새 600자
발췌가 포함한 한 사례에서 발생했다. **구조 자체의 효과나 전체 에이전트 정확도 향상을 입증하는 결과는 아니다.**

## 조건과 재현

- 모델: 실행 시 사용자 설정의 `anthropic / claude-opus-5 / medium`.
- 8개 영어 합성 사례 × 3방식 × 2회 = 실제 요청 48회. 두 반복의 정답 여부는 모두 같았다.
- 격리한 임시 DB에 원문과 명시적인 interpretation을 넣고 실제 읽기 구현을 사용했다.
  검색 후보는 고정하며 검색·관계 추출의 정확도와 자율적인 후속 도구 사용은 평가하지 않는다.
- 세 방식에 같은 질문·시스템 프롬프트를 사용했다. 정답·채점용 원문은 요청에 넣지 않았다.
  기존 읽기는 새 응답에서 `evidenceContext`만 제외하고, 추적은 기존 `trace_evidence`를 호출했다.
- 입력 추정 상한 6,000토큰, 추정 여유율 25%, 출력 상한 2,048토큰. 같은 **상한**이며 실제 입력량은 다르다.
  이번 tokenizer는 `o200k_base` fallback을 사용했다. 실측 최대 입력 추정은 1,050토큰이다.
- 직렬 요청, 사례·반복별 방식 순서 회전, 요청당 90초 timeout. 전송 실패를 오답으로 처리하지 않고 실행을 중단한다.
- 노드 기록 시각은 포함하지만 별도의 질문 시각은 제공하지 않았다. 추가 읽기는 허용하지 않았다.

저장소 루트에서 worker 산출물을 준비한 뒤 실행한다. 기본 실행은 모델을 호출하지 않는다.
현재 구현은 설치본의 출력 상한 계약을 확인한 Anthropic 구독 공급자만 지원한다.

```sh
vp run memory-agent#build
vp run --no-cache memory-agent#eval:structured-memory
MEMORY_EVIDENCE_OUTPUT=/tmp/structured-memory-live.json vp run --no-cache memory-agent#eval:structured-memory -- --live
```

전체 입력 스냅샷·실제 답변·인용·usage·개별 점수는
[원시 결과](structured-memory-benchmark-2026-10-15.json)에 있다. 원문은 모두 합성 데이터다.
프로필 ID와 인증 정보는 저장하지 않는다. 호출 시각·공급자 상태·비결정성 때문에 재실행 답변은 달라질 수 있다.

## 결과

| 지표                         |    기존 읽기 | 기존 읽기 + 추적 |   구조화 읽기 |
| ---------------------------- | -----------: | ---------------: | ------------: |
| 정답률                       |   8/16 (50%) |      12/16 (75%) | 14/16 (87.5%) |
| 모든 필수 근거가 포함된 입력 | 2/16 (12.5%) |      12/16 (75%) | 14/16 (87.5%) |
| 필수 근거 구절 포함률        |   6/20 (30%) |      16/20 (80%) |   18/20 (90%) |
| 필수 근거 구절 인용률        |   6/20 (30%) |      16/20 (80%) |   18/20 (90%) |
| 철회·교체된 값을 답한 횟수   |         8/16 |             2/16 |          2/16 |
| 잘못된 JSON 응답             |            0 |                0 |             0 |
| 평균 실제 입력 토큰          |        476.1 |            873.8 |         932.1 |
| 평균 실제 출력 토큰          |        142.5 |            223.8 |         216.1 |

정답은 사전 정의한 값과 대소문자·양끝 공백 정규화 후 정확히 비교한다. 근거 포함은 사례별
필수 구절이 입력에 있는지, 인용은 원문에 존재하는 인용의 source ID와 해당 필수 구절을 비교한다.
이는 의미 기반 판정이 아니라 고정 문자열 기준이다. 사례별 필수 구절 수가 달라 총 20개가 된다.
두 반복은 같은 8개 사례를 재사용하므로 독립된 16개 사례로 해석하면 안 된다.

| 사례                       | 정답    | 기존 읽기 | 기존 읽기 + 추적 | 구조화 읽기 |
| -------------------------- | ------- | --------- | ---------------- | ----------- |
| 직접 정정                  | SOUTH   | NORTH     | SOUTH            | SOUTH       |
| 대안 없는 철회             | UNKNOWN | LOCAL     | UNKNOWN          | UNKNOWN     |
| staging만 바뀐 조건부 정정 | 7412    | 7412      | 7412             | 7412        |
| 미확정 제안                | 8       | 8         | 8                | 8           |
| 변경 전 시점 질문          | ALPHA   | ALPHA     | ALPHA            | ALPHA       |
| 원인 노드의 대상 정정      | UNKNOWN | UNKNOWN   | UNKNOWN          | UNKNOWN     |
| 기존 300자 발췌 밖 정정    | VIOLET  | AMBER     | UNKNOWN          | VIOLET      |
| 교체된 결정의 후속 철회    | UNKNOWN | SILVER    | GOLD             | GOLD        |

모든 행은 두 반복에서 동일하다. 기존 읽기가 맞힌 조건부·미확정·원인 정정 사례도 필요한 최신
근거 전체를 가진 것은 아니므로 정답률과 근거 포함률을 따로 보고한다.

## 해석과 남은 검증

주 비교인 기존 읽기+추적에 비해 구조화 읽기는 실제 입력 토큰을 약 6.7% 더 사용했다.
관계·상태·원문 구절을 한 도구 결과에 제공할 수 있었지만, 관측한 정답률 차이는 더 긴 발췌가
설명한다. 동일한 근거량에서 JSON 구조 자체가 추론을 개선하는지는 별도 비교가 필요하다.

후속 철회는 `SILVER → GOLD → 철회`에서 마지막 철회가 두 결과 모두에 없어서 실패했다.
현재 계약은 대체 원문 자체를 다시 읽도록 요구한다. 이번 실험은 그 후속 조회를 금지했으므로
자율 에이전트가 실제로 이 안내를 따르는지 평가하지 못했다. 질문 시각 추가와 후속 근거 추가를
분리해서 검증해야 한다.

대규모 공개 벤치마크, 다국어, 긴 대화의 실제 검색, 잘못 추출된 관계, 자율 후속 조회는 미평가다.
이 결과를 전체 사용자 질의에 대한 정확도나 철회된 값의 사용 차단 보장으로 확대하지 않는다.
