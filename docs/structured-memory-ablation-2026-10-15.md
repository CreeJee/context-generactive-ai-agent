# 질문 시각·후속 조회·표현 방식 비교 (2026-10-15)

질문 시각 추가만으로는 후속 철회 오답이 해결되지 않았다. 철회 원문을 후속 조회하면 JSON·문장형
모두 정답을 냈다. 이 사례군에서는 표현 방식보다 근거 누락이 관측한 실패를 설명한다.

사용자가 제안한 두 가능성을 [첫 실험](structured-memory-benchmark-2026-10-15.md) 이후에 분리해 검증했다.
후속 철회 누락이 질문 시각 부재 때문인지, 근거를 충분히 조회한 뒤에도 표현 구조가 답변에 영향을 주는지가 대상이다.

## 비교 조건

같은 8개 사례에 네 조건을 각각 2회 적용한다. 모델은 `anthropic / claude-opus-5 / medium`으로 유지하고
첫 실험의 답변을 재사용하지 않는다. 총 64회 새 요청을 보내며, 정답과 점수 기준은 첫 실험과 같다.

| 조건                  | 질문 시각 | 대체·정정 근거 후속 조회 | 표현                  |
| --------------------- | --------- | ------------------------ | --------------------- |
| `structured-read`     | 없음      | 없음                     | 기존 구조화 JSON      |
| `structured-at-time`  | 있음      | 없음                     | 기존 구조화 JSON      |
| `structured-followup` | 있음      | 있음                     | 구조화 JSON           |
| `narrative-followup`  | 있음      | 있음                     | 같은 정보의 영어 문장 |

질문 시각은 모든 합성 사건이 기록된 뒤의 시각으로 고정한다. 원문의 `createdAt`과 부가 근거의
`recordedAt`은 첫 조건에도 원래 들어 있다. 질문 시각을 원문의 사실 적용 시점으로 간주하지 않는다.

후속 조회는 최초 응답의 `changes[].source.id`를 한 차례씩 실제 `readStructuredEvidence`로 읽는다.
모델이 찾을 ID를 정답에서 주입하지 않는다. 다만 조회 실행은 벤치마크가 강제하므로 자율 도구 사용의
성공률은 측정하지 않는다. 재귀 전체 탐색이나 새로운 저장 관계는 추가하지 않는다.

마지막 두 조건은 같은 도구 결과 객체를 공유한다. 문장형 변환은 모든 원문을 그대로 유지하며
노드 ID·종류·프로젝트·세션·기록 시각·detail·길이·UTF-16 위치·이어 읽기 위치·판정·관계 대상·상태·
생략 개수·범위 제한을 문장에 옮긴다. 단순한 내용 요약이나 관계를 제거한 원문 목록이 아니다.
따라서 이 비교는 **동일 정보의 JSON 표현과 명시적인 문장 표현** 사이의 비교이며, 관계 정보가 없는
비구조화 메모리 전체와의 비교는 아니다. 두 조건의 토큰 길이는 같지 않다.

모델 호출 전 8개 사례 모두에서 마지막 두 조건의 내부 context가 같고 모든 원문 블록이 문장형
입력에도 그대로 존재함을 확인했다. 후속 철회 사례의 필수 구절은 앞 두 조건에 없고 뒤 두 조건에 있다.

## 재현

기본 실행은 32개 입력만 생성한다. 실제 호출은 `--live`가 필요하다.

```sh
vp run --no-cache memory-agent#eval:structured-memory -- --ablation
MEMORY_EVIDENCE_OUTPUT=/tmp/structured-memory-ablation-live.json vp run --no-cache memory-agent#eval:structured-memory -- --ablation --live
```

입력 추정 상한 6,000토큰·25% 여유율, 출력 상한 2,048토큰, 요청당 timeout 90초, 직렬 실행과
방식 순서 회전은 첫 실험과 같다. 입력 프롬프트와 실제 응답을 원시 결과에 함께 기록한다.

## 실측 결과

64회 요청이 모두 완료됐고 JSON 형식 실패는 없었다. 두 반복의 정답 여부는 모든 조건에서 같았다.
원문·정답·실제 프롬프트·응답·usage·개별 점수는 [원시 결과](structured-memory-ablation-2026-10-15.json)에 있다.

| 지표                         |   구조화 읽기 |   + 질문 시각 |  + 후속 조회 | 같은 근거의 문장형 |
| ---------------------------- | ------------: | ------------: | -----------: | -----------------: |
| 정답률                       | 14/16 (87.5%) | 14/16 (87.5%) | 16/16 (100%) |       16/16 (100%) |
| 모든 필수 근거가 포함된 입력 |         14/16 |         14/16 |        16/16 |              16/16 |
| 필수 구절 포함률             |   18/20 (90%) |   18/20 (90%) | 20/20 (100%) |       20/20 (100%) |
| 필수 구절 인용률             |   18/20 (90%) |   18/20 (90%) | 20/20 (100%) |       20/20 (100%) |
| 철회된 값을 답한 횟수        |          2/16 |          2/16 |         0/16 |               0/16 |
| 평균 실제 입력 토큰          |         934.9 |         958.9 |       1327.4 |             1332.4 |
| 평균 실제 출력 토큰          |         220.8 |         216.4 |        215.0 |              209.6 |

실측 최대 입력 추정은 1,363토큰이었다. 마지막 두 조건의 평균 실제 입력 길이 차이는 약 0.4%다.
입력 길이를 억지로 같게 맞추지는 않았다. 실측 입력에서도 마지막 두 조건의 context 객체가 같고
모든 원문 블록이 문장형에 보존됐음을 확인했다.

후속 철회 사례에서 앞 두 조건은 두 번 모두 `GOLD`, 뒤 두 조건은 두 번 모두 `UNKNOWN`을 답했다.
나머지 7개 사례는 네 조건 모두 두 번씩 정답이었다. 모델은 후속 철회 원문이 있을 때
`SILVER → GOLD → 철회, SILVER도 계속 폐기`를 근거로 답했다.

## 해석과 다음 경계

- **이번 실패는 질문 시각 추가로 해결되지 않았다.** 원문 기록 시각은 원래 있었고, 질문 시각을
  추가해도 빠진 철회 사실이 복원되지 않았다. 다른 종류의 시간 추론에서도 시각이 불필요하다는 뜻은 아니다.
- **연결된 근거를 더 읽는 효과는 확인했다.** 다만 조회가 강제된 실험이다. 실제 에이전트가 대체
  근거를 추가 조회하는지, 긴 정정 사슬을 예산 안에서 끝까지 확인하는지는 아직 미검증이다.
- **동일 정보에서 JSON의 추가 우위는 관측하지 못했다.** 두 표현 모두 관계와 시간 정보를 명시한다.
  결과는 필드의 필요성을 부정하지 않으며, 현재 스키마가 모든 추론에 충분함을 보증하지도 않는다.
  8개 합성 사례를 반복한 작은 표본이고 후속 조회 조건은 모두 맞혀 더 어려운 차이를 드러내지 못한다.

다음 검증 대상으로는 기록 시각과 효력 시점이 다른 결정, 미래 적용·과거 소급 정정, 조건부 철회,
여러 후보가 충돌하는 긴 사슬, 실제 에이전트의 후속 조회 수행을 권한다. 이것들은 이번 PR에서
제품 동작이나 저장 스키마를 추가 변경하지 않고 평가 항목으로 남긴다.

## 검증

- JSON·문장형의 동일 context와 모든 원문 보존: dry-run 및 실측 입력 8쌍 확인.
- 두 번의 실제 모델 비교: 첫 실험 48회 + 이번 실험 64회 완료.
- `vp check`: 오류·경고 0.
- `vp run typecheck`: error 0, 기존 미지원 warning 17곳(출력 18회)으로 exit 1 유지.
