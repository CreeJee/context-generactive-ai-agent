## Pre-change request and storage path

- `ChatPanel` configures TanStack history with `pageSize: 50`; the hydrate adapter sends `limit=50` and uses `before` for older pages.
- `apps/agent/app/routes/api/chat.tsx` forwards the request through `AgentChat.hydrate`.
- `AgentChat.hydrate` first verifies the session exists, then delegates non-stream requests to `ChatState.hydrate`. Stream replay uses a separate authenticated run/session and offset path and must remain separate.
- `ChatState.hydrate` materializes a missing legacy thread, then invokes SDK `reconstructChat` with a thread/session equality authorization gate.
- `sqliteChatPersistence.loadThread` currently selects the complete `chat_threads.messages` JSON and parses it before considering paging. A limit does not limit storage reads. Legacy IDs are synthesized using the full-thread position. A `before` cursor slices the already-parsed messages; the SDK subsequently converts and slices UI messages.
- Consequently, 50 returned UI messages do not prove bounded database reads, JSON parsing or UI conversion.
- Installed `@tanstack/ai-persistence` is 0.6.7. `reconstructChat` forwards `limit=pageSize+1`, so the UI's 50 becomes a store hint of 51. It converts to UI messages before applying the final newest window.
- Returning an array for an older hinted request causes the SDK to call `loadThread(threadId)` again without options. A real `MessagePage` result avoids that fallback. When the converted page exceeds the UI page size, the SDK replaces an adapter cursor with the first retained UI ID; the storage cursor resolver must support this behavior.
- The SDK's subagent-card reconstruction can recursively load complete child transcripts, but only when `runs.listByParentRun` is supplied. The current SQLite run store does not implement that optional method. Do not report this SDK path as an observed active bypass in this app; protect against enabling it unintentionally.
- `reconstructChat` resolves the active run before reading the transcript, then reads pending interrupts. Preserve that ordering: the writer saves the final transcript before marking a run complete.

### SDK page-boundary requirements

Direct inspection of installed SDK `reconstruct.ts` lines 148–184 and 380–432 confirms these implementation requirements:

- A store limit is a UI-window hint, not proof that slicing that many raw ModelMessage rows is correct. The SDK converts the returned model rows first; raw split/merge boundaries must be resolved before a storage range is selected.
- Return `MessagePage` for hinted requests. Returning an array for `before` invokes `loadThread(threadId)` again and converts the complete transcript.
- The adapter must resolve both its own cursor and the first retained UI message ID: when conversion produces more than the requested UI page size, the SDK replaces the adapter cursor with that UI ID. A raw-ID-only cursor index is not sufficient without proving ID correspondence.

These are verified SDK contracts, not evidence that the current storage adapter implements bounded reads. The adapter still selects/parses the full JSON and ignores the initial limit.

## Projection transition contract (before implementing its schema)

- Keep `chat_threads` and its complete model transcript authoritative and unchanged. The projection is disposable derived storage in separate tables; its format version is local to its metadata, not a new global `PRAGMA user_version`. Existing app migrations remain untouched. This is not permission to downgrade unrelated schema changes already present in a database.
- Store one UI group per `(thread_id, ordinal)` with a unique indexed UI ID and the complete model messages belonging to that group. Read only the requested groups by the composite ordinal index; resolve retained UI-ID cursors with the unique index. Check whether earlier rows exist without loading an extra group's payload.
- Mark a projection stale on every authoritative transcript update, including a 0.0.13 writer update. Never use a timestamp-only freshness comparison. Deletion removes the derived rows and metadata even when foreign keys are disabled. A modern writer will replace the original and the derived snapshot under one savepoint. ID collision keeps the original and must not publish ambiguous cursor IDs.
- Backfill occurs in a separate preparation path, not in initial/older page reads: build groups from a complete transcript, atomically publish only the current snapshot, and track completion per thread. A failed/interrupted thread remains unavailable/stale; retry does not alter original records. Page reads of stale/unprepared data return an explicit non-ready result, not a hidden full-transcript fallback. The production adapter must provide a preparation/error policy before rollout; SQL primitives alone do not enable it.
- Rollback removes only projection triggers/tables. It does not lower global `user_version`, rewrite transcripts, or undo unrelated migrations. The 0.0.13 three-value writer and original content must still work after removing the projection. End-to-end release migration/opener tests are separate from isolated SQL contract tests.
- Validate ready initial/older reads, EXPLAIN index access and bytes returned, stale/old-writer/delete invalidation, atomic replacement and rollback, UI conversion equivalence, cursor boundaries, concurrent append, and collision policy before connecting this cache to the live adapter. Production migration/backfill and before/after HTTP/UI measurement remain mandatory.

### Effect reader boundary (not yet installed in production)

`HistoryProjectionReader` is a Context/Layer service that borrows the existing `Database` connection; it neither creates/closes a DB nor starts a runtime/background task. A named Schema-derived request model validates positive integer page sizes and non-empty cursor/thread IDs before executing a single prepared snapshot statement. DB row shapes are Schema-decoded. Responses distinguish unprepared/stale/unsupported-format from unknown cursors and valid pages. Only selected groups are put in chronological ordinal order; next cursor is the earliest selected UI ID when earlier rows exist.

The selected model-message JSON stays opaque at this layer. The future SDK adapter must decode these selected groups with its model-message codec, not read or parse the authoritative transcript. Preparation must install the disposable schema before building the reader layer. Missing tables produce a typed `SqliteRead/prepare` failure; invalid request, query and row failures remain distinct, safe reasons and are not converted to empty history.
