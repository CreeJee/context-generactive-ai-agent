# Local semantic recall sensor: S1 feasibility and contract

Status: S1 source review of the approved `@receptron/laya` Node ONNX multilingual candidate. No Laya installation, automatic recall, or model integration is enabled by this document.

## Existing boundaries (2026-10-04)

- `packages/memory-agent/src/agent/chat.ts` handles new user turns separately from internal follow-ups and tool/approval continuations; redacted user text is persisted as evidence. A new recall sensor must run at most once per admitted new turn, never as a side effect of every provider continuation. The external-agent branch uses a separate `memoryPreamble`; do not change that branch in this experiment.
- `packages/memory-agent/src/agent/compaction.ts` prepares each model-bound request, but calls `retrievalAppendix` only when original content was omitted (`stage !== "none"`). The appendix is best-effort and inserted before the latest user message. The new-turn trigger is not a substitute for this behavior; shadow mode must not change its provider-bound messages or durable evidence.
- `packages/memory-agent/src/memory/search.ts` performs project-scoped vector/text/morph rank fusion followed by graph traversal. The existing manual `find_memory`, `read_evidence`, and `trace_evidence` tools remain independent. A trigger score is **not** a ranked node list for RRF. A future automatic search must explicitly pass `crossProject: false` rather than relying on `find`'s cross-project default.
- Local embedding uses a CPU or WebGPU model (`packages/memory-agent/src/memory/embedding/embedder.ts`); its concurrent memory, accelerator and energy contention with another local model needs measurement before activation.

## Contract for a future, replaceable sensor (design only)

1. **Input:** a single admitted new user turn, redacted/minimized text and only the allowed recent same-project context needed to resolve deictic references. No full tool results, cross-project history, credentials, attachments, or opaque model-provider prompts. The input budget is bounded; neither raw evidence nor approved user decisions may be altered.
2. **Output:** `disabled | skipped | unavailable | timeout | error | evaluated`, and for an evaluated turn a finite _uninterpreted score_ and model/runtime version, plus elapsed time. Do not describe it as a calibrated probability; do not fix a threshold before validation. Store only bounded, non-content telemetry in shadow mode, if any; no message/evidence/graph-edge mutation.
3. **Trigger:** decides only whether a search _might_ be useful. Query construction from permitted recent context is separate. Candidate-relative hints such as `retracts_candidate` require retrieved candidates and must not create `corrects`/`retracts` edges or user decisions.
4. **Failure:** disabled, unsupported hardware, low-resource mode, cancellation, timeout and other failures all mean _no new automatic search_. Existing provider request, compaction appendix, external-agent preamble, and manual tools retain their existing behavior. Release the managed model session on shutdown; avoid duplicate evaluation for continuations of the same turn.
5. **Locality:** default no remote endpoint or silent model download. The candidate uses an in-process Node ONNX session, not a Python HTTP sidecar. Explicit user opt-in is required before any nonlocal transfer/download; errors must not fall through to a cloud service. Any future service alternative would require same-machine loopback binding, managed lifetime and cleanup, and a separate review.

S2 will define the thresholds, hardware and evaluation budgets using measured data rather than example values. S3 may implement this contract only after the feasibility review below identifies a suitable local artifact.

## Distribution feasibility — Node ONNX candidate, source review (2026-10-06)

The approved candidate is [`@receptron/laya`](https://github.com/receptron/laya), the Receptron Node/TypeScript SDK, with the **multilingual** ONNX bundle. It replaces the previously proposed Python loopback path as the candidate for this investigation; it does not enable inference. The source review below is pinned to GitHub commit [`6478649e723122ca24bbf5fb69ed1010023c9750`](https://github.com/receptron/laya/tree/6478649e723122ca24bbf5fb69ed1010023c9750), whose package metadata reports version `0.1.2`. The public npm registry independently reports `@receptron/laya` version `0.1.2`, MIT and Node >=20 (2026-10-06); installed-package equivalence was not checked.

### Verified upstream source facts

- [Package metadata](https://github.com/receptron/laya/blob/6478649e723122ca24bbf5fb69ed1010023c9750/package.json) declares **Node >=20**, ESM, `onnxruntime-node` and `@huggingface/tokenizers`. [README](https://github.com/receptron/laya/blob/6478649e723122ca24bbf5fb69ed1010023c9750/README.md) describes Node inference without Python/PyTorch at runtime. The SDK is **MIT** ([LICENSE](https://github.com/receptron/laya/blob/6478649e723122ca24bbf5fb69ed1010023c9750/LICENSE)); model weights remain **Apache-2.0** according to the README and [ONNX model card](https://github.com/receptron/laya/blob/6478649e723122ca24bbf5fb69ed1010023c9750/onnx/README.md). Dependency licenses remain unaudited.
- [`Laya.load(options)`](https://github.com/receptron/laya/blob/6478649e723122ca24bbf5fb69ed1010023c9750/src/laya.ts) creates a tokenizer and ONNX session with default `executionProviders: ["cpu"]`, overridable by session options. A nonempty `modelDir` resolves a local directory and **bypasses `ensureBundle` entirely**; Hugging Face download options are ignored. This is the candidate's source-verified no-download loading path, not yet a measured guarantee about all dependency/runtime network behavior.
- [`src/download.ts`](https://github.com/receptron/laya/blob/6478649e723122ca24bbf5fb69ed1010023c9750/src/download.ts) defaults to Hugging Face repo `receptron/laya-onnx`, revision `main`, with the root representing English. The remote multilingual selector is **`subfolder: "multilingual"`**. For offline admission, pre-stage an approved, revision/digest-pinned multilingual bundle and pass its actual directory as `modelDir`; adding `subfolder` to `modelDir` options does not select or append a variant. The five required files are `laya.onnx`, `laya.onnx.data`, `laya_config.json`, `tokenizer/tokenizer.json`, and `tokenizer/tokenizer_config.json`.
- Without `modelDir`, the downloader uses `cacheDir`, otherwise `LAYA_CACHE`, otherwise `XDG_CACHE_HOME` (or `~/.cache`) plus `receptron-laya`; it partitions by repo/revision/subfolder. Even an existing cache causes remote **HEAD** freshness requests; missing or size-mismatched files cause GET downloads. A failed HEAD permits existing files to be reused, but a cache alone is **not a no-network mode**. No digest validation is implemented there; same-size cache checks are not integrity verification.
- The public API is `await laya.systemOne(state, questions)`, with a **question-ID-keyed object** of discriminated `choice | score | noul` questions and an `answers` object keyed by the same IDs ([types](https://github.com/receptron/laya/blob/6478649e723122ca24bbf5fb69ed1010023c9750/src/types.ts), [implementation](https://github.com/receptron/laya/blob/6478649e723122ca24bbf5fb69ed1010023c9750/src/laya.ts)). Questions are batched into one session run; an empty question set throws. `choice` returns a label/distribution; `score` is the expected **ordered-level index**, not a probability; `noul` is the rounded true-option probability (`p[1]`) after temperature-scaled softmax, not a boolean. `confidence` for choice/score is distribution entropy-derived and distinct from `rl_agent.act_probability`; the Node `NoulAnswer` has no `confidence` field.
- `await laya.close()` calls `session.release()`; upstream says not to use the instance afterwards. This releases the session, not cache files. Future integration must own load/close lifetime and bounded admission. The reviewed public API does not expose cancellation or a deadline for `systemOne`; a timeout policy must not be mistaken for verified interruption of native inference.

### Interpretation and locality lifecycle

The README calls `noul` a “calibrated P(true)”. The implementation applies checkpoint temperature values, but this **does not establish calibration for our recall questions, Korean/mixed-language turns, or traffic**. Treat the returned value as an uncalibrated signal for this application until held-out evaluation supports a threshold. Do not map ordered `score` to `P(memory_required)`, infer truth or user approval from any answer, or adopt an illustrative `0.35` threshold.

The README's **about 1.7 GB fp32 weights**, **roughly 2 GB loaded-model RAM plus a few hundred MB per batch**, and warm Apple-silicon timing are upstream rough claims, **not measurements on this host or validated multilingual resource budgets**. Exact multilingual artifact size, hardware compatibility, peak/steady memory, latency, contention with local embeddings, and energy cost remain runtime gates.

Proposed lifecycle, not executed: obtain explicit download consent; stage a dedicated, pinned multilingual bundle and verify its digest/ownership; admit only supported resources; load through `modelDir`; evaluate only permitted minimized text; fail closed with no cloud fallback; release with `close()` on shutdown/removal. Remove only the dedicated owned bundle/cache after release, never a shared cache. SDK/dependency acquisition also needs staging or consent. External forwarding hooks and browser demos are excluded. Packet capture/network denial checks remain necessary to verify offline behavior of the complete runtime; reviewing the SDK's loader alone cannot prove absence of telemetry or dependency network calls.

### Existing integration and remaining gates

The previously prepared HTTP/mock adapter in `packages/memory-agent/src/agent/recall-sensor.ts` is **not a Node SDK integration**; matching question-ID object shapes does not make the transports interchangeable. This S1 update makes no code changes. Current insertion point and production wiring are checked separately; the existing default-unconfigured shadow preparation must not be treated as permission to activate the new candidate. No UI setting or automatic model startup is introduced here.

**S1 result:** the approved Node ONNX multilingual candidate has a source-verified local-directory loading path and session cleanup API. Python HTTP serving is no longer the chosen path. No package/model was installed, downloaded, or run, and no user text was sent for inference. Before real-turn activation, verify artifact provenance/digests, installed SDK correspondence, resource admission, measured offline operation, failure/timeout/shutdown behavior and held-out calibration. Preserve existing manual search, compaction retrieval, external-agent preamble and durable evidence boundaries; if gates fail, retain mock/heuristic evaluation only.
