# 기억 그래프 자동 정리

임베딩 설정을 직접 선택한 저장소에서 앱 시작 시 실행한다. 설정 화면의 ‘기억 그래프 정리’에 진행 상황과 변경 건수를 표시한다. 정리는 로컬 SQL과 기존 벡터 삭제만 사용하며 모델을 호출하지 않는다.

최초 실행은 기존 노드를 순서대로 확인해야 한다. 이후에는 저장한 커서부터 재개하고, 완료된 정리 버전은 다시 순회하지 않는다. 새 데이터는 가져오기·해석·검색 단계의 필터로 보호한다. 이는 모든 의미 오류를 판별하는 품질 평가가 아니라, 확인 가능한 구조 오류와 빈 발화로 생긴 잡음을 정리하는 작업이다.

## 저장 기록

- `memory_graph_maintenance`: 버전별 대상 상한, 커서, 상태, 변경 건수.
- `memory_graph_edge_repairs`: 변경 전 연결과 역방향 연결을 새로 추가했는지 여부.
- `memory_graph_interpretation_repairs`: 변경 전 해석 상태.
- `memory_graph_suppressed_nodes`: 검색에서 제외한 토픽. 원문 노드는 유지한다.
- `memory_graph_topic_candidates`: 재개 가능한 토픽 확인 대기열.
- `memory_graph_vector_removals`: 모델별 벡터 삭제 대기열. 비활성 모델은 다음에 열 때 처리한다.

64개 노드씩 DB 트랜잭션으로 변경하고, 벡터 파일 저장이 성공한 뒤 삭제 대기열을 지운다. 파일 저장 실패는 상태에 표시되며 다음 시작 시 재시도한다. 인덱서와의 잠금은 배치 단위이고, 정리 작업 전체가 인덱싱을 막지 않는다.

## 되돌리기

앱을 종료하고 DB와 벡터 디렉터리를 함께 백업한 뒤 복사본에서 복원을 검증한다. 스키마의 `user_version`을 낮추거나 정리 테이블을 삭제하지 않는다.

정리 버전의 `memory_graph_edge_repairs`에서 `action = 'reverse'`이고 `replacement_added = 1`인 경우에만 새 역방향 연결을 제거한다. 보관한 원래 연결은 원래 방향·종류·가중치·시각으로 복원한다. `memory_graph_interpretation_repairs`의 원래 상태도 복원한다. 이후에 같은 연결이나 해석을 변경했다면 자동으로 덮어쓰지 말고 비교한다.

해당 버전에서 제외한 토픽의 삭제 대기열을 먼저 지우고 `memory_graph_suppressed_nodes`를 해제한다. 이미 삭제된 벡터는 그 토픽만 다시 인덱싱한다. 다른 모델의 대기열이 아직 처리되지 않았다면 기존 벡터를 그대로 사용할 수 있다. 원문이 남아 있으므로 전체 임베딩을 새로 만들 필요가 없다. 완료 상태는 유지해야 같은 정리를 다시 적용하지 않는다.
