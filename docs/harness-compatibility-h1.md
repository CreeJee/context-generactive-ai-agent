# H1: TanStack Codex / Claude Code harness compatibility spike (2026-09-30)

**Scope:** A no-credentials fixture test of the published adapters and their stream translators, not a provider integration test or approval to change the live runtime. `SubscriptionTextAdapter`, OAuth storage and chat routes were not changed. No Codex/Claude CLI, `localProcessSandbox` (which is **not** an isolation boundary), actual account, internal quota endpoint or provider inference was used.

## Historical experiment — not a workspace package

The one-off synthetic fixture and its `tools/harness-spike` workspace package were removed on 2026-10-03. No product code imported this package; retaining a second TanStack core version and external CLI SDK dependencies in the monorepo was unnecessary. The observations below are historical evidence, not current integration tests or a command to run deleted files.

The original experiment used a separate temporary folder because this repository pins `@tanstack/ai` **0.61.0**, whereas those adapter versions require **^0.63.0** and `@tanstack/ai-sandbox` **^0.5.17**. A future adoption decision would require a new isolated experiment against then-current versions, not restoration of a permanent workspace for H1.

Pinned versions tested: `@tanstack/ai` 0.63.0, `@tanstack/ai-sandbox` 0.5.17, `@tanstack/ai-codex` 0.5.14, `@tanstack/ai-claude-code` 0.7.1, `@openai/codex-sdk` 0.159.2, `@anthropic-ai/claude-agent-sdk` 0.3.285. Packages were installed **only** in `/tmp` using `--ignore-scripts`. The tested adapter implementations spawn the harness executables (`codex exec --experimental-json` / a runner invoking `claude -p --output-format stream-json`) inside a `SandboxCapability`; they do not turn the current app's OAuth client into an SDK account handle. See installed `src/adapters/text.ts` in the respective package for this version's command and auth settings.

## Observations (fixture 5/5 pass)

| Contract               | Observed result                                                                                                                                                                                                                                                                                                                             | Migration consequence                                                                                                                                                                                                                                                                                                                        |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Minimum events         | Synthetic Codex and Claude events produce AG-UI `RUN_STARTED`, text, bridged MCP tool call + **already-resolved** tool result, `RUN_FINISHED`, usage tokens and a harness-session-id `CUSTOM` event.                                                                                                                                        | UI rendering is potentially reusable, but tokens/cost of **this run** are not subscription remaining quota. No live model output or executable was tested.                                                                                                                                                                                   |
| Sandbox                | Calling `chat()` with either adapter **without** `withSandbox` rejects before a CLI/provider call.                                                                                                                                                                                                                                          | A real integration needs sandbox middleware and an isolation policy/provider; `localProcessSandbox` alone runs on the host and cannot substantiate credential isolation. Default Claude Code permission mode `bypassPermissions`, Codex default approval `never` in these package sources: do not connect to app tools/workspace by default. |
| Existing approval loop | The app uses `needsApproval`/TanStack interrupt and permission review before running selected tools. Codex emits completed tool results from its own loop; Claude has a _separate_ sandbox policy permission-prompt bridge that denies, emits approval-requested and requires a rerun when asked.                                           | **Not a drop-in match** for the app's existing pending tool-call interrupt/resume contract or report-session read-only tools. An explicit permission/result mapping and deny-by-default policy would need a separate, end-to-end test in a truly isolated sandbox. Fixture tests did **not** execute/approve tools.                          |
| Conversation resume    | Each translator reports an independent Codex/Claude session id. `buildPrompt(messages, sessionId)` sends only the trailing user message and resumes that harness session; without it, it flattens prior text turns (not a faithful tool transcript).                                                                                        | App `threadId`/durable transcript does not automatically equal harness `sessionId`. Must persist and scope the harness ID to app conversation, provider, **account**, workspace, and permissions; test interrupted runs and reattachment before adopting.                                                                                    |
| Account A/B            | Current subscription runtime binds `createAccountBoundSubscriptionClients.forRun()` to the selected account when its adapter is created; existing account-bound tests cover that behavior. The harness factories take model/config, `authMode: 'host'` reads CLI login in its environment; there is no per-app-profile credential argument. | **Unverified / incompatible without a new design:** switching the UI account cannot be assumed to switch a CLI's active login, its refreshed tokens or an existing harness session. Never mount/copy all users' CLI homes or reuse one harness session across accounts. No account credential was accessed by H1.                            |
| Quota                  | Synthetic Claude `rate_limit_event` generated no AG-UI quota event in the tested translator; ordinary `RUN_FINISHED.usage` contains run-level tokens (optional cost), not personal-plan utilization/reset. Codex translator likewise emits run tokens, not subscription limits.                                                             | M5 remains blocked; no quota integration or OAuth authorization is implied by either adapter. See [M4 research](subscription-quota-research.md).                                                                                                                                                                                             |
| Auth/policy            | Harness host login is tied to the CLI environment and does not grant this product permission to embed Claude.ai login. [Anthropic authentication/credential guidance](https://code.claude.com/docs/en/legal-and-compliance.md#authentication-and-credential-use) limits third-party Claude.ai login and credential intermediation.          | **Do not ship custom Claude.ai OAuth via the harness.** Supported API-key or properly constrained unmodified CLI flows require a separate decision.                                                                                                                                                                                          |

**Additional boundary:** Codex's tested `buildCommand()` places a per-run host-tool-bridge bearer token in a command-line `--config ...http_headers...` value when tools are exposed. This is not an account OAuth token, but it is still a sensitive capability that may appear in process listings or diagnostics. Do not enable that bridge for report-session tools without a separate exposure/redaction and permissions review. H1 did not instantiate the bridge or run that command.

## Verification and next gate

- `/tmp` installed packages with lifecycle scripts disabled; `node --test fixture.ts`: **5 passed, 0 failed** (synthetic events, sandbox required, prompt resume). `pnpm exec vp test packages/memory-agent/tests/oauth-account-bound.test.ts packages/memory-agent/tests/subscription-adapter.test.ts`: **21 passed** (baseline app behavior).
- **Not tested:** sandbox process startup, real tool approval/deny/retry, account switch while a harness runs, cross-process durable resume, live sign-in, real output, official quota response, network boundaries or provider terms approval.
- Keep `SubscriptionTextAdapter`. Before _any_ production migration: decide allowed Anthropic auth model and A/B account isolation, choose a genuinely isolated sandbox, map approval and harness session lifetime, update TanStack core/dependencies, then test these end to end without leaking tokens. The H1 fixture passing is **not** permission to implement M5's internal endpoints or to claim account-specific quota figures.
