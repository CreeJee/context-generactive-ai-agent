# Local subscription OAuth accounts (M2 / M3)

The local web server exposes `GET /api/accounts?provider=openai|anthropic` and same-origin-only `POST /api/accounts` with `{ "provider": "openai" | "anthropic", "intent": "add" | "cancel" | "select" | "remove" | "rename", "label"?: string, "accountId"?: string }`. `add` requires a nonblank label (up to 80 characters) and returns a pending authorization URL to open in a browser. Poll `GET` for `login.status` (`pending`, `completed`, `error`, `idle`). `cancel` stops a pending callback. `select`, `remove`, and `rename` require an ID from the provider's `profiles` list; `rename` also requires a label. Responses include secret-free local profile IDs, labels, selection and creation time, not inferred provider email or subscription limits. Responses are `Cache-Control: no-store`. The authorization URL is only returned during the pending OAuth flow; do not log, share or put it in a report.

Each new login gets a distinct random ID and OS-keychain slot; the pre-existing provider login slot is never used to add a new profile. Publishing happens only after the callback saved its credential. Cancelling during callback persistence restores the earlier contents of that slot. Explicit removal of an imported legacy account removes both the copy and old slot and records a DB tombstone, so status polling cannot silently re-import it. If vault deletion fails, the account metadata remains for a retry; do not interpret a generic `account_action_failed` response as a completed removal. No account IDs or labels authenticate a request by themselves; the local server's existing same-origin checks apply to mutations.

**M3 runtime boundary:** The app's default provider registry resolves the selected provider-scoped profile for authentication and model catalogues. Model caches are keyed by profile, and a newly created chat adapter pins its profile-specific OAuth client so later account switches do not redirect its stream/refresh. An account switch to a profile whose catalogue does not include the previously selected model returns `model_unavailable_for_account` (HTTP 409) when that catalogue is available; choose a supported model first. An in-process run lease blocks vault removal for its pinned provider/profile (including legacy onboarding) until the durable chat stream finishes or an early return releases it. A concurrent removal blocks new runs on that profile; the API returns a generic 409, so retry after the run. This transient guard is per local server process and is not a cross-process vault lock. The web sidebar controls and a real two-account OAuth/keychain test remain deferred to U2/I5, respectively. Provider-issued refresh-token revocation or identity uniqueness cannot be guaranteed from a local label.
