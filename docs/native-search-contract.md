# Native memory search contract

2026-10-08 (Asia/Seoul), Goal v7 / Plan v15, updated during `native-search-04-repair`.

## Execution and module boundary

- TypeScript owns host services, authorization, embedding/morph analysis, Effect orchestration, graph expansion and correction/provenance policy.
- One dedicated Node worker owns the existing turbovec index and CacheLease. The audited current runtime has no search-owning worker to reuse. Do not create a second VectorIndex Layer or a second lease.
- Existing `packages/turbovec/src/lib.rs` low-level N-API methods and index format remain intact. Read-only git comparison confirms that crate manifest and binding currently match 0.0.13, including engine revision ccab9f325e6ce2a270a87daf01ae4e443bcf2d49; preserve that engine revision while adding the read-session dependency/module. Add a separate `memory_search` Rust module in that crate and an additive read-session binding. The read session receives the worker's existing index **only for the duration of a call**; it does not copy, reopen or store an unsafe borrowed index pointer.
- Rust opens SQLite read-only, with query-only mode, for candidate/FTS/morphology/batch lookup work. It never migrates, writes node/vector mappings, or takes over Node's SQLite writer. Use the configured trusted DB file, not a path from public search input. Reject `:memory:` for this cross-thread read-session path; existing in-memory tests retain the legacy path, and paired benchmarks use scoped file/WAL storage.
- Heavy synchronous N-API calls occur only inside that owning worker. Promise and Effect adapt actual worker messages; neither is permission to call heavy N-API on the host thread.

## Request and response

Internal request envelope: literal `kind: "search"`, unique request ID, owner epoch, expected published generation, caller context correlation, normalized query Float32Array, separate host-classified trigram/short-substring/morph terms, authorized project IDs, embedder identity, per-channel seed budgets and a private Rust-owned request-control capability carrying cancellation and an Instant deadline. Host searchTerms classification uses existing JavaScript UTF-16 length semantics; Rust must not reclassify by UTF-8 bytes or Unicode scalar count. Preserve term order, FTS quote escaping and short-term substring case sensitivity. No candidate seq allowlist crosses this request boundary.

Bounded query vectors are copied at submission; do not detach or mutate the embedder/caller's buffer. Host preflight charges eight logical bytes per array entry before Schema decoding/owned copies, in addition to UTF-8 contents and vector bytes; empty entries cannot conceal an unbounded array. Before payload validation/copy/queueing the host registers a lightweight native SearchControl. It stores an Instant deadline and Arc<AtomicBool> cancellation state; native search consults that same state after transport and N-API conversion. No Rust/JS clock epoch comparison, run_script or mutable JS intrinsic is used. NativeReadInput.remainingMs remains a compatibility DTO field; the registered native deadline is authoritative. Control registration converts only bounded identity/budget scalars before its deadline begins; large request preparation/queue/transport/conversion afterward is included, not a hard deadline guarantee.

The requested output budget bounds successful search payload logical bytes, not exact serialized frame size. On failure, empty channel arrays plus a fixed error/metrics envelope may exceed a tiny requested payload budget; this envelope is separately bounded (no user text/candidate arrays) and is not a success or budget bypass. Stage metrics are wall times; optional workerBoundaryCpu measures thread CPU around the entire N-API boundary, including conversion/SQLite, not pure engine CPU. No hard deadline or mid-scan CPP preemption is implied.

Caller correlation stays in the host pending registry and is matched against epoch/request ID on every completion. It contains owner/run/session identifiers, not model instructions or authorization tokens. Only a trusted host service constructs allowed project IDs. An empty allowed list returns empty batches; it never means all projects.

Validate finite vector elements, exact index dimensions, finite safe host limits, canonical sequence IDs, bounded term/project byte lengths and deadline at admission and the native boundary. Do not silently clip authorized projects. If a scope or response exceeds its explicit resource bound, return budget-exceeded rather than alter top-k authorization. Keep IDs as canonical decimal strings at the native boundary; only convert to legacy numeric seq when safely representable.

Result is a literal-tagged union, branched with `switch`:

- `success`: bounded vector/text/morph ranked batches and coverage, owner epoch, generation, seed node IDs and rank/scores, safe stage metrics.
- `degraded`: available bounded batches, explicit unavailable channels, coverage and same generation metadata. Preserve existing channel-degradation behavior; no invented successful channel.
- `cancelled`: request termination acknowledgement, no applicable hits.
- `budget-exceeded`: queue/execution/input/output budget category, no silently truncated successful search.
- `stale-generation`: observed epoch/generation or unpublished/poisoned state; no applicable hits. At most one bounded retry on a newer published generation if the same caller is still live; never retry cancellation.
- `error`: typed validation/queue-full/worker-unavailable/read/index failure code and safe diagnostic category. No SQL body, database contents or secret-bearing native error string in logs or public diagnostics.

The first high-level implementation returns bounded channel rankings, not a rewritten final memory policy. Existing TypeScript `fuseRanks`, tie handling and graph/correction/provenance processing remain the reference. Batch-map vector IDs in SQLite; do not SELECT once per native hit. Return no raw document text from the native seed stage. Coverage/project-name lookups may be batched as required without expanding into a graph migration.

For caller limit L, preserve vector k=4L and morph k=2L. Text is not globally capped at 2L: preserve trigram top-2L followed by each two-character term's top-2L substring results in term order, deduping exactly as the host does. Its maximum length derives from the number of terms and the DTO byte budget. Global clipping to 2L would change RRF ranks/recall and is forbidden. Preserve host tuning.text, exact-first ordering and exactTextWeight. Do not reduce recall to satisfy a transfer target. Native search request/response DTOs each have a 1 MiB logical payload budget (Float32 bytes plus UTF-8 string fields, with returned scalar/ID fields accounted separately). Exceeding it is explicit budget-exceeded, never an authorization-list truncation or a partial successful seed ranking. Oversized provenance in the final host policy must use an explicit budget/error contract, not lose corrections silently. This byte budget does not claim exact V8/N-API resident allocation size.

## SQLite snapshot / index publication

Index generation is an ephemeral actor epoch plus monotonic counter, not a new persisted column or file format. Restart changes epoch and invalidates all pending handles/results. Generation is not SQLite `user_version` or a claim that all graph writers share a transaction.

Before admission, validate that no vector mutation/publication is pending; recheck epoch/generation/published state at the owner immediately before actual job execution to close the admission-to-execution race. Existing active reads finish before acknowledging an unpublished writer interval. Begin a Rust read transaction and establish its SQLite snapshot with a real first read (BEGIN alone is insufficient) before enumerating project-filtered candidate seqs. Use that one transaction for all ranked channels and batch ID mappings. The actor serializes calls so its index cannot mutate during that transaction. Return the same published generation, then release the transaction before another job. Do not open a separate transaction for each channel.

Vector publication uses one lightweight host-owned gate associated with the existing storage owner and shared explicitly by all participating light/full runtime writer services; do not rely on Layer memoization across independent ManagedRuntimes to manufacture one gate. Purge must not acquire a second VectorIndex Layer or require model initialization just to enter the gate. The gate covers the **existing complete writer operation**, not individual RPC methods. Mark unpublished before its first DB or native mutation, reject or wait boundedly for queued reads, and preserve mutation-specific ordering:

1. Add: after embedding finishes, reacquire the gate and revalidate current node existence, original text and eligibility before add. Deleted/changed nodes are skipped/requeued, never resurrected by a late embedding. Then native add → existing `.tmp` save/atomic `index.tvim` rename → Node `Database.atomic` mapping commit.
2. Maintenance removal: suppression and durable removal intent DB commit → native remove/save → existing mapping/journal cleanup commit. The gate includes the initial suppression/intent commit.
3. Redaction: native remove/save → existing text/FTS/mapping commit, preserving its existing order and recovery rules.
4. Purge: participate in the same gate and exclude late pending embedding publication; use existing targeted removal/reconciliation for orphaned cached vectors if cleanup is needed. Do not create a new journal schema. Native candidate joins must always exclude deleted nodes/mappings.
5. Publish the next generation only after the complete operation's successful acknowledgement, release the gate, and admit new searches. Separate caller interruption from publication lifetime: finish the finite commit section or leave state explicitly poisoned; interruption/finalizers must not release it as clean.

An add/save/mapping failure must not publish a clean generation. Keep durable removal intent and the current flush/reconcile/rebuild recovery contract. While state is poisoned, searches return stale-generation/index-unavailable; no silent fallback to synchronous host search. Bootstrap reconciles the old index/mappings exactly as the existing owner does before publishing its first ready generation. Moving file/lease ownership must not make the Rust read connection responsible for those SQLite repairs.

Existing import connections can commit unrelated nodes/FTS/edges while a search is running. WAL makes the Rust read snapshot coherent; these writers do not mutate the leased index. Any existing writer path that invalidates indexed text must participate in the vector publication gate or leave the existing durable invalidation/removal intent before the next admitted search. Audit those paths before integration; do not infer serialization from the Database service's comment.

Host graph/provenance expansion remains current TypeScript policy, not a second long-lived SQLite transaction across `await` on the shared writer connection. Recheck allowed projects/current node existence during expansion and discard late/obsolete caller results. The native snapshot guarantee covers ranked seed channels and mappings; it does not falsely claim all later graph metadata is one cross-thread atomic snapshot. If the final caller requires stronger all-graph snapshot semantics, that is a design revision, not implicit whole-graph Rust migration.

## Effect / cancellation / lifetime

Expose a lazy Effect service adapter over a framework-neutral async host client. Submit only when the Effect runs; do not wrap an already-running Promise. Scope acquires one worker and closes it once. Individual Fiber interruption cancels that request, never the shared worker. Expected native failures belong in the typed error channel; interrupted Fibers remain interruptions rather than retriable search failures.

Fix public-caller assertions during integration: current project always included, other projects respect cross_recall_excluded, default crossProject=true; every channel retains meaningfulNodeFilter. Global meaningful embeddedKinds unindexed coverage stays global, while uninterpreted coverage remains allowed-project-scoped. Preserve foundBy (including morph-only as text), complete, 300-character snippet, utility rounding, projectName/fromOtherProject, ordered supersededBy and unconfirmedChallenges. Host embedding/morph failure is represented as per-channel availability; analyzer identity none does not add morph degradation. Global cancellation, budget, stale-generation or worker loss must bypass the old broad vector catch and fail/interupt the whole request, not masquerade as text-only success. Typed whole-request failures propagate through MemorySearch's Effect error channel and the existing safe tool/API error boundary; no fabricated successful FindResult.

At most 32 admitted searches, one active index-owner search. Keep the admission queue on the host and post only the dispatched active job; otherwise messages queued behind a synchronous worker call cannot satisfy the queued-cancel bound. Remove queued jobs immediately on interruption. Count an active job against admission/resources until actual termination, even if its caller waiter has been detached. A writer publication gate has priority over newly admitted readers; avoid starving deletes/save. Default total work deadline is two seconds, including queue wait. Saturation is a typed queue-full response, not unlimited pending Promises.

Queued abort removes the pending job and settles within 50 ms. Active abort acknowledges within 100 ms through a shared atomic flag visible to Rust and SQLite's progress handler; a `cancel` worker message alone cannot interrupt a synchronous native call. The existing turbovec primitive has no proven mid-scan cancellation hook: check before and after that call and explicitly report the residual non-preemptible span. Require measured-size admission bounds or a cooperative engine hook before claiming active-cancel/deadline guarantees; if insufficient remaining budget or an unsupported size prevents such a bound, return budget-exceeded before entering that stage, never truncate candidates or declare termination while CPU work still runs. A timeout cannot falsely attest that CPU resources are already released. If measured spans cannot satisfy the deadline/cancellation bound, do not enable the new default; add a genuine cooperative boundary or revise the contract with evidence.

Cancellation memory is Rust-owned Arc<AtomicBool>; no JS backing-store pointer, typed-array root or SAB brand validation participates. SearchControl registration uses a host-private UUID entropy seed plus a never-recycled native serial capability. Duplicate active seed registration is rejected; reuse of a seed after close produces a different capability and cannot revive an old message. The bounded process-wide registry holds at most 4,096 live controls, with no unbounded retired-token set. Claim checks private owner key, epoch and request ID and succeeds only once. Main-thread cancel/close accesses only the originating handle's Arc and never touches the index/SQLite writer or sends cancellation to a blocked worker. Worker/SQLite callback holds its own Arc until actual completion, so host interruption/close cannot free live callback storage. Effect acquireUseRelease closes controls on rejection, queued/running interruption, normal completion, failure and Scope shutdown; active transport slots still wait for actual replies. A close is not a hard-preemption claim.

Snapshot validation rejects noncanonical and duplicate IDs before declaring full mapping identity. Explicit read completion clears the progress callback and confirms rollback/autocommit; cleanup failure poisons the connection and returns a literal read-failed owner error, never success/reuse. Drop is a best-effort fallback only. No persistent schema/index format changed.

Distinguish host cancellation acceptance, native flag observation, and actual job/transaction termination. Only the third permits a cancelled termination result and resource release. Measure residual turbovec scans, busy waits, row conversions and serialization as well as SQLite progress-handler intervals. The native read connection's busy timeout must fit its remaining request budget, never inherit the Node writer's five-second busy timeout. Published vector generation is not a global DB transaction version: unrelated imports may produce different valid SQLite snapshots within one generation.

Native resources remain owned until the actual job exits, even after the caller stops waiting. Release the read transaction/SQLite statements on all tagged outcomes. Scope shutdown stops admission, cancels/drains requests under a finite deadline, terminates the worker only if necessary, and awaits cleanup before accepting a replacement lease owner. Failed worker exit settles every pending request in its own epoch. Do not auto-retry writes or automatically replay a crashed publication.

## Implemented controlled vector primitive — limits, not a hard guarantee

`VectorIndex.searchControlled(query, k, controlToken, ownerKey, epoch, requestId, allowedIds?)` is additive to the unchanged legacy low-level API/engine revision. The worker claims the Rust-owned Arc/Instant capability once, checks cancellation/budget before and after the exact existing engine call and after output conversion, and returns typed empty outcomes rather than partial success. Host interruption cancels the originating control directly outside the blocked worker. Registration precedes large request preparation; admission/wait registration is interruption-masked so a cancelled Fiber cannot leave an untracked queued job.

Measured-envelope policy: index ≤50k, exactly 384 dimensions/4-bit, k≤48, allowlist length≤50k, and at least 12 ms remaining. Unsupported work is budget-exceeded before scoring, not clipped. These numbers are policy derived from the fixed fixture, not a worst-case proof. The current native function can overrun a requested deadline during mask construction, cold cache preparation or scoring, then discard results after return. It cannot force mid-scan termination. Neither configured work budget nor post-call checking implies hard CPU cancellation; default activation still requires the full criteria.

The previous SAB pointer/brand-intrinsic implementation is superseded by `04-repair`, not an alternative supported safety boundary. Its visibility/GC observations remain historical normal-path evidence only. Current Rust-owned control and addon fingerprints were separately validated on the same fixture; cancellation-window timestamps include FFI conversion, not a scoring midpoint. No compromised-realm safety, forced worker-isolate GC, mid-scan preemption or hard-deadline proof is inferred from either measurement.

## Compatibility / rollback / evidence

Native-search adds no SQLite migrations and leaves pre/post-change schema/user_version unchanged; it does not alter original transcript/model context, index.tvim, or remove low-level N-API APIs. Baseline is GitHub release 0.0.13, not experimental 0.0.14-canary1. The current build already contains migrations beyond 0.0.13; both original/current openers reject a higher schema version. Therefore rollback below means the same current build's legacy owner, not an in-place downgrade of the current DB to the original 0.0.13 binary. Verify 0.0.13 format/writer behavior on isolated release-compatible fixture or original backup, and upgrade/restore on copies. Do not add schema downgrade tooling or claim an original binary opens the migrated current DB. Additive native exports require normal application/native packaging, with current source/addon fingerprints in verification.

An operator-controlled switch selects the legacy or new owner path at startup. Exactly one selected owner acquires CacheLease. Rollback drains/closes the new owner before the old path starts; it is not opening a legacy index alongside the new one. Keep the default legacy until fixed quality/consistency and paired performance criteria pass. Do not restart the running backend as a side effect of contract work.

Minimum implementation proofs: unchanged fixed ranks and allowed-project behavior, generation/publication races, finite IDs/dimension rejection, queue/abort/budget/worker-exit cleanup, removal/save recovery and 0.0.13 code rollback. Reuse existing fixtures; no broad SQL/install test suite. Safe native stage counters distinguish candidate/FTS/vector/batch work and logical boundary sizes without exposing SQL/user content. Old native-boundary CPU remains an aggregate, not pure inner turbovec CPU.
