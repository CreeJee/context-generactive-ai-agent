# Map·Set 사용처 검토 (2026-10-06)

## new Map 재검토

1차 검토에서 지역 인덱스·상수·테스트·Node 경계라는 이유로 native Map을 넓게 허용한 판단을 수정했다. `apps`, `packages`, `tools`의 실제 생성식을 AST로 찾고, 해당 77개 파일에서 생성식의 소유자·조회·갱신·삭제·반환과 호출부를 재검토했다. 문자열 속 테스트 예제와 의존성·빌드 산출물·스킬 예제는 제외한다. 기존 미커밋 파일도 포함한 작업 트리 기준이다.

- native Map: 147곳에서 5곳으로 감소, 4개 파일에만 남는다.
- 키별 공유 잠금은 RcMap과 Semaphore로 획득·반납한다. 응답 대기는 Deferred와 Ref<HashMap>으로 소유한다.
- tokenizer 재사용은 Effect Cache로 관리한다. 상수는 HashMap, 갱신하는 지역 인덱스는 MutableHashMap을 사용한다.
- 내부 인덱스라는 이유만으로 native Map을 허용하지 않는다. native Map 유지 사유는 실제 SDK/wire 표현 계약 및 그 계약의 테스트로 한정한다.
- 삽입 순서, 중복 키의 마지막 값, boolean 삭제 결과, 캐시 회수 조건, 실패 및 취소 전달을 보존한다.
- 이번 재검토의 중심은 Map이다. 기존 Set 검토의 범위를 확대하지 않았으며 현재 Set 생성식은 180곳이다.
