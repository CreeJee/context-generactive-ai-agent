# 검색 결과의 최신 근거 포인터 비교 (2026-10-16)

`find_memory` 결과에 정정/철회 사슬의 끝(`latest`)을 붙이면, 강제 1단계 후속 조회보다 적은 입력으로
긴 사슬과 모순 갈라짐에서 더 많이 맞혔다. 12개 합성 사례·2회 반복의 작은 파일럿이다.

## 질문

[이전 비교](structured-memory-ablation-2026-10-15.md)에서는 대체 원문을 한 번 더 조회하면 후속 철회 사례를
맞혔다. 다만 그 조회는 평가기가 강제했고, 사슬이 한 단계보다 길면 닿지 못한다. 검색 결과 자체를 마지막
근거로 바꾸지 않고, 결과마다 "기록된 변경이 끝나는 곳"을 포인터로 알려 주면 충분한지 확인한다.

## 제품 동작

- `latest`는 같은 판정 규칙(`isChangeAuthority`)을 만족하는 applied 정정/철회만 따라간다.
  순환과 깊이 6에서 멈추며 순위·검색 후보는 바꾸지 않는다.
- `unchanged`: 기록된 변경 없음. `changed`: 끝이 하나. `branched`: 끝이 여럿.
- 한 사실은 한 시점에 값이 하나이므로 `branched`는 이상 신호다. 정정이 잘못된 대상에 연결됐거나,
  한 메시지가 여러 사실을 담았거나, 실제 모순이다. 어느 경우인지는 원문으로만 알 수 있어 하나를 고르지 않고
  각 끝에 기록 순서(`recordedRank`, 1이 최신)를 붙인다.
- `unconfirmedAfter`는 사슬 위에 미확정 변경이 있음을, `truncated`는 깊이 제한에 걸렸음을 뜻한다.

## 비교 조건

모델은 `anthropic / claude-opus-5 / medium`, 모든 조건에 질문 시각을 넣는다. 12개 사례 × 3조건 × 2회 = 72회.

| 조건                  | 입력                                                                    |
| --------------------- | ----------------------------------------------------------------------- |
| `structured-read`     | 원문의 `read_evidence` 결과                                             |
| `structured-latest`   | 같은 결과 + 고정 후보의 `find_memory` `latest` 포인터                   |
| `structured-followup` | 같은 결과 + `changes[].source.id`를 한 번씩 `read_evidence`로 강제 조회 |

기존 8개 사례에 4개를 더했다. 이 사례들은 `--latest`에서만 생성해 이전 보고서의 재현을 바꾸지 않는다.

- `three-step-chain`: 4100 → 4200 → 4300 → 4400 정정 사슬.
- `replacement-with-pending-idea`: 대체 원문 뒤에 미확정 제안이 붙음.
- `bundled-facts-branch`: 한 메시지의 운영·스테이징 포트를 각각 정정 (정당한 갈라짐).
- `contradicting-branch`: 같은 사실에 서로 다른 정정 두 개 (모순, 정답 `UNKNOWN`).

검색 순위는 평가 대상이 아니다. 고정 후보에 `MemorySearch.latest`가 실제로 붙이는 값을 그대로 넣는다.

## 재현

```sh
vp run --no-cache memory-agent#eval:structured-memory -- --latest
MEMORY_EVIDENCE_OUTPUT=/tmp/latest-evidence-pointer.json vp run --no-cache memory-agent#eval:structured-memory -- --latest --live
```

## 해석과 한계

- **긴 사슬은 포인터로만 풀렸다.** 1단계 후속 조회는 4300에서 멈췄다. 포인터는 조회 없이 끝을 알려 준다.
  후속 조회보다 평균 입력이 약 17% 적다.
- **모순 갈라짐에서 다른 두 조건은 기록 순서상 뒤의 값을 골랐다.** 두 정정의 기록 시각은 사실상 같다.
  `branched` 신호가 있을 때만 판단을 보류했다.
- **정당한 갈라짐에서 한 번 과하게 보류했다.** 스테이징 정정의 "only the staging port changes"를 운영 포트
  유지로 읽고 두 끝이 충돌한다고 판단했다. 사례 문구도 이 해석을 허용하므로 갈라짐 신호의 비용과 사례
  모호성이 섞여 있다.
- 합성 사례의 노드는 같은 밀리초 근처에 기록돼 실제 대화의 시간 간격을 반영하지 않는다.
  12개 사례·2회 반복이며 검색 순위나 자율 에이전트의 도구 사용은 측정하지 않았다.
- 같은 사실에 대한 갈라짐 대부분은 해석이 정정을 사슬 끝이 아닌 원래 노드에 연결해서 생길 것으로 본다.
  쓰기 시점에 대상을 사슬 끝으로 보정하는 작업은 별도로 다룬다.
