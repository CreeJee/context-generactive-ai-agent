# 문제 제보 첫 버전

- 로컬 웹서버가 응답할 때 사이드바 **리포트하기** 또는 `/report` 페이지에서 작성한다. 정상 채팅의 `/report` 명령은 같은 페이지로 이동하는 편의 기능일 뿐, 승인 대기나 채팅 중단 시에는 버튼/URL을 쓴다.
- 증상만으로 문안 생성·복사 가능하다. 최근 증거는 사용자가 별도로 불러오고, 원문을 확인한 뒤 항목별로 포함·편집한다. 저장된 대화 노드·도구 노드 발췌와 Work Trace 작업 locator는 모델 제공자의 원시 HTTP 출력이 아니다.
- Discord 게시·TXT 첨부는 사용자가 직접 한다. 앱은 게시하거나 웹훅/토큰을 저장하지 않는다.
- 원본 대화와 분리된 전용 분석 세션을 열 수 있다. 서버가 원본 세션·프로젝트를 바인딩하며, 분석용 읽기 전용 근거 도구는 그 범위 안에서만 조회한다. 분석 세션을 열지 못해도 증상 제보문 작성·복사·저장은 계속 가능하다. 관측 근거와 모델 추정은 구분해야 하며, 모델 호출 실패가 필수 제보를 막아서는 안 된다. 이 구현·검증이 원본 증거의 외부 전송 동의나 새로운 비용 정책을 승인한 것은 아니다.
- 자동 오류 감지·로컬 이벤트 보존·Discord/webhook 발송은 후속 작업이다. 웹서버 자체가 접근 불가능한 장애도 첫 버전 범위 밖이다.
- 보안 경계: 현재 제품은 단일 사용자 로컬 loopback 서버이며 별도의 사용자별 계정 ACL이 없다. 보고 API는 세션과 프로젝트 ID의 실제 관계를 확인하고 건수/문자 수를 제한한다. 노드는 저장 시 비밀정보 탐지/마스킹을 거치지만, run 오류 문자열이나 사용자 텍스트에서 모든 민감 정보가 제거된다는 보장은 없다. Discord에 올리기 전 원문과 복사 문안을 직접 확인해야 한다. 로컬 서버를 여러 사용자에게 노출하려면 먼저 인증과 세션별 권한을 추가해야 한다.

## 검증 범위

- 자동 검사: `pnpm exec vp check`, `pnpm exec vp run agent#typecheck`, `pnpm exec vp test apps/agent/app`, `pnpm exec vp run agent#build`. 독립 라우트 서버 렌더, 잘못된 프로젝트/세션 쌍의 404, 제한된 증거와 부분 실패, 선택적 포함 및 클립보드 거부가 테스트된다.
- 수동 확인 필요: 실제 브라우저에서 승인창 반복/실행 장애를 유발한 상태에서 사이드바 버튼 및 `/report` 직접 접속, 증거 조회 실패 시 문안 선택·복사, 긴 증거 TXT 다운로드 및 Discord 붙여넣기. 이 검증은 자동 테스트만으로 완료했다고 주장하지 않는다.
