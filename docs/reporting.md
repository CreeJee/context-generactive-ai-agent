# 문제 제보

- 로컬 웹서버가 응답할 때 사이드바 **리포트하기** 또는 `/report` 페이지에서 작성한다. 정상 채팅의 `/report` 명령은 같은 페이지로 이동하는 편의 기능일 뿐, 승인 대기나 채팅 중단 시에는 버튼/URL을 쓴다.
- 증상만으로 문안 생성·복사 가능하다. 최근 증거는 사용자가 별도로 불러오고, 원문을 확인한 뒤 항목별로 포함·편집한다. 저장된 대화 노드·도구 노드 발췌와 Work Trace 작업 locator는 모델 제공자의 원시 HTTP 출력이 아니다.
- 원본 대화와 분리된 전용 분석 세션을 열 수 있다. 서버가 원본 세션·프로젝트를 바인딩하며, 분석용 읽기 전용 근거 도구는 그 범위 안에서만 조회한다. 분석 세션을 열지 못해도 증상 제보문 작성·복사·저장은 계속 가능하다. 이 구현·검증이 원본 증거의 외부 전송 동의나 새로운 비용 정책을 승인한 것은 아니다.
- **AI 진단(선택)**: 사용자가 누를 때만 `POST /api/reports/diagnosis`로 사용자가 선택한 모델에 한 번 요청한다. 작성한 설명과 포함·편집한 증거만 보낸다. 결과는 `관측`(포함한 증거 ID 인용)과 `가설`(검증되지 않은 추정)로 나뉘고, 인용이 없는 관측은 서버가 가설로 옮긴다. 각 항목은 편집·삭제할 수 있고 제보문 포함 여부를 고른다. 모델 사용 불가(503)·호출 실패(502)·형식 오류(422)여도 제보문에는 실패 사실만 적고 사용자 설명·증거는 그대로 남는다.
- **Discord 웹훅 전송(선택)**: 사용자가 개발자에게 받은 웹훅 주소를 제보 페이지에서 설정하면, 검토한 최종 문안을 **누를 때만** 그 웹훅으로 보낸다. 주소는 코드에 없고 OS 키체인(`report-discord-webhook`)에만 저장되며, API 응답·제보문·오류에는 웹훅 ID 끝 4자리만 나온다. 실패하면 이유를 보여주고 복사·텍스트 파일 저장은 항상 남는다. 자동 오류 감지·로컬 이벤트 보존은 후속 작업이고, 웹서버 자체가 접근 불가능한 장애는 범위 밖이다.
- 보안 경계: 현재 제품은 단일 사용자 로컬 loopback 서버이며 별도의 사용자별 계정 ACL이 없다. 보고 API는 세션과 프로젝트 ID의 실제 관계를 확인하고 건수/문자 수를 제한하며, 변경 요청은 same-origin만 받는다. 노드는 저장 시 비밀정보 탐지/마스킹을 거치지만, run 오류 문자열이나 사용자 텍스트에서 모든 민감 정보가 제거된다는 보장은 없다. 전송·복사 전에 최종 문안을 직접 확인해야 한다. 로컬 서버를 여러 사용자에게 노출하려면 먼저 인증과 세션별 권한을 추가해야 한다.

- 자동 검사(2026-10-12, 이 브랜치): `vp check`와 `vp run typecheck`는 이 브랜치가 바꾼 파일에서 새 오류가 없다. 남은 오류는 기준 main(`a4c8740`)에 이미 있던 `apps/agent/server/tests/*`의 삭제된 `testRuntime` 참조와 `backend-restart.test.ts`, `read-only-bar.tsx`뿐이다.
- 집중 테스트: `packages/memory-agent/tests/integrations/report-delivery.test.ts`(로컬 가짜 HTTP 서버로 전송·`allowed_mentions`·첨부·`wait=true`, 같은 문안 중복 인식과 확인 후 재전송, 짧은 429 대기, 404 중단, 응답 미확인 후 `uncertain_duplicate`, 동시 전송 `in_progress`, URL 형식), `report-diagnosis.test.ts`(인용 없는 관측의 가설 이동, 형식 오류), `subscription-quota.test.ts`(계정별 조회 불가 사유), `apps/agent/app/entry/report/*.test.tsx`(관측·가설 구분 문안, 진단 실패 시 최소 문안), 사이드바 브라우저 테스트(접힌 프로젝트 이름만, 계정 목록·한도 상태·전환).
- **실제 Discord 수신은 검증하지 않았다.** 실제 웹훅·네트워크로 보낸 적이 없고, 전송 검증은 로컬 가짜 서버에 한정된다. 실제 채널 수신·표시(첨부 미리보기, 2000자 경계, 멘션 차단)는 사용자가 개발자 웹훅을 받아 직접 확인해야 한다.
- 모델 진단은 실제 모델을 호출하지 않았다(유료 호출 금지). 격리 실행에서는 로그인이 없어 `model_unavailable` 폴백 경로만 확인했다.
- 수동 확인 필요: 실제 브라우저에서 승인창 반복/실행 장애를 유발한 상태에서 사이드바 버튼 및 `/report` 직접 접속, 증거 조회 실패 시 문안 선택·복사, 긴 증거 TXT 다운로드 및 Discord 붙여넣기.
